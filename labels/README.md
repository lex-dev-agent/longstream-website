# Bottle labels

Print-ready label artwork, rendered from HTML by headless Chrome.

```
node scripts/render-label.js                     # everything
node scripts/render-label.js classic-blonde      # both sides of one label
node scripts/render-label.js classic-blonde-back # one side
```

Output lands in `labels/out/` (not committed):

- **`<name>.pdf`** — the deliverable. Trim plus 3mm bleed plus crop marks. The
  type stays live text, so the printer can pull the fonts out of it.
- **`<name>.png`** — for looking at. Trim area only, 300 DPI, no bleed or marks.

Each label is a plain HTML file with **one stylesheet of its own**, in
millimetres throughout. Nothing is shared between labels except `fonts.css`,
which declares typefaces rather than design and so cannot carry a layout change
from one to another — every label repeats the page chassis instead. That
duplication is deliberate: on print files, being certain that an edit reaches
exactly one label is worth more than the lines it saves.

Opening a label's `.html` in a browser shows the same thing the renderer
produces, so it is fine to nudge things there and then re-render.

## What the renderer checks

Two things fail silently in print work, so the script reports both:

- **Overflow.** The type sits in an absolutely positioned box, so anything that
  does not fit is simply cut off at the foot of the label. The script prints
  how many millimetres over it is.
- **Substituted fonts.** When Chrome cannot embed a face it does not error — it
  swaps in Georgia or Segoe UI and writes a PDF that only looks wrong on paper.
  The script lists any typeface in the PDF that `fonts.css` did not declare.

## Two versions of the front

Open `labels/compare.html` in a browser — no server needed — to see them side
by side. Two controls: scale %, and Live / PNG. **Live** shows the label pages
themselves, so Inspect reaches the real elements; **PNG** shows what
`render-label.js` last wrote to `out/` — the trim only, no bleed or crop marks,
which is the better view for judging the label itself. The labels are in iframes rather than copied in,
so the page cannot drift from the real artwork and Inspect reaches the actual
elements.

`classic-blonde-front.html` is the one to suggest. `classic-blonde-ross-front.html`
is Ross's, from his mockup on the Label Notes tab of the working doc — saved as
`old/ross-front-and-back-spec.png`, along with `old/ross-sealer-spec.png` for the
anti-tamper strip, which nothing here renders yet.

They are the same label — same chassis, same layout, same vertical rhythm —
but each has its own stylesheet, so the two can be pulled apart freely. What
differs is the four things he specified:

| gin type | DRY GIN | LONDON DRY GIN |

| tasting | Crisp and Warm Spice · Lime Finish | Crisp warm spice with a lime finish |

## Where this is up to

Both sides are the old label — `labels/old/blonde-gin-classic-v5-front.png` is
the front it was matched against — on the new trim sizes. Nothing from the
working doc has been applied yet.

The label is drawn at the old label's **height** (123.8mm) and at whatever
width the new trim needs, then scaled uniformly so that height becomes 115mm:

```
--s: calc(115 / 123.8)          one scale, set by height alone
.label width  = trim width / --s     drawn wide, not scaled wide
```

Because the scale is uniform, every vertical measurement lands at the same
percentage down the label as it did on the old one — type sizes, gaps, the
portrait. Because the canvas is drawn wider rather than scaled wider, nothing
is stretched horizontally: the extra width is just room. Checked against the
reference, the brandline, portrait, DRY GIN, location, tasting note and specs
all land within a couple of percent of where they sat before.

Every value inside `.label` is the old label's own, unchanged, converted at
1px = 0.305mm and 1rem = 4.88mm. Convert anything new the same way.

One consequence worth knowing when editing: **nothing is sized as a plain % of
width**, because a percentage resolves against the wider canvas and grows with
it. Two ways round that, both in use:

- The gold rule and the DRY GIN divider are measured against `--old-w`, so
  they stay the width they were rather than running out towards the new edges.
- The portrait is measured from the **height**. The old rule was
  `width: 117%`, which on a wider canvas would blow it up, so it is
  `height: 118.1%` — the same size on the old label, stable on this one.

## Sizes and standards

Trim sizes are from Ross's brief — front 130 × 115, rear 90 × 115. The bleed is
drawn as an extension of the gold border rather than as white, so a cut landing
a millimetre out still lands in gold instead of exposing the dark bed.

The back is still the old back: description, address, warning and the
pregnancy warning. The barcode window, bottle-number window and energy panel
from the doc are not on it yet.

## Two figures to settle when the doc's changes go on

- **Energy panel.** The brief gives 254 kJ per 33mL serving and 854 kJ per
  100mL. Those disagree: 854 kJ/100mL works out to 282 kJ for a 33mL serve,
  not 254. Neither is on the label yet.
- **Standard drinks.** The back currently says 22.5, which is the old label's
  figure. 700mL x 38% x 0.789 g/mL = 210 g of alcohol, and at 10 g per NZ
  standard drink that is 21.0 — the doc's figure, and the correct one.
- **Pregnancy warning size.** The brief asks for an 8mm pictogram circle *and*
  4mm text. The supplied artwork cannot give both: its proportions are fixed,
  so an 8mm circle puts the statement text at about 2.6mm. That clears the
  2.1mm legal minimum, but it is not 4mm — 4mm text would need a 12.5mm circle
  and a block roughly 70mm wide. The label currently carries the old label's
  size (30.5mm wide), which puts the circle at about 5.4mm — under the 6mm
  minimum, so this one does need changing.
